# Інструкції для Claude Code

## Референси

У `reference/` зберігаються приклади для ознайомлення, а не кодова база цього фреймворку:

- `reference/playwright-test-automation-template/` — приклад структури Playwright + TypeScript: UI/API/E2E тести, fixtures, Page Objects, компоненти, моделі, сервіси, фабрики даних і `storageState`. Ліцензія — MIT.
- `reference/design-patterns-typescript/` — навчальні приклади GoF-патернів на TypeScript. Це не Playwright-фреймворк. Ліцензія — CC BY-NC-ND 4.0.
- `.claude/skills/playwright-best-practices/SKILL.md` — додатковий довідник із локаторів, перевірок, очікувань, структури тестів і мокування API, взятий із [GenAIEventHub](https://github.com/RomanMakarenko/GenAIEventHub/blob/claude/eventhub-updates/.claude/skills/playwright-best-practices/SKILL.md). Це рекомендації з іншого проєкту, не джерело конфігурації для цього фреймворку.

## Домовленості щодо реалізації

- `docs/IMPLEMENTATION_PLAN.md` — це дорожня карта та джерело статусу фаз, а не підтвердження, що заплановане вже реалізовано. Позначай фазу виконаною лише після проходження її критеріїв приймання.
- Будуй тести на нативній моделі Playwright Test: використовуй типізовані fixtures через `test.extend`, а де можливо — вбудовані `page`, `context` і `request`. За замовчуванням зберігай ізоляцію на рівні тесту; worker-scoped fixtures застосовуй лише для свідомо спільного й безпечного стану. Не перенось Java/TestNG lifecycle, DI чи thread-local driver patterns.
- Тримай повторно використовуваний код фреймворку в `src/`, а тестові набори — у відповідних каталогах `tests/`. Узгоджуй TypeScript, ESLint і конфігурацію Playwright із поточним CommonJS-режимом у `package.json`; змінюй формат модулів лише як окреме перевірене рішення.
- Для Docker узгоджуй версію офіційного Playwright-образу з версією Playwright у кореневому lock-файлі. Передавай секрети лише під час запуску; не додавай облікові дані чи `storageState` до образу, репозиторію, логів або артефактів. Зберігай звіти й результати тестів доступними поза контейнером; для CI за можливості використовуй те саме версійно узгоджене середовище.

## Як використовувати

1. Спершу перевіряй структуру, залежності та домовленості **цього проєкту**. Референси не є вимогою копіювати їхню архітектуру.
2. Використовуй Playwright-шаблон для пошуку конкретних прикладів ідей; переглядай лише файли, що стосуються поточного завдання. Адаптуй рішення до потреб проєкту, не копіюй шаблон цілком і не змінюй файли всередині референсів.
3. Для актуальної поведінки та API Playwright орієнтуйся насамперед на офіційну документацію: <https://playwright.dev/docs/intro>. Перед використанням прикладу звіряй його з версіями залежностей у кореневому `package.json`.
4. Із `playwright-best-practices/SKILL.md` застосовуй лише загальні рекомендації, якщо вони відповідають цьому проєкту. Його приклади написані на JavaScript і містять специфічні для EventHub URL, селектори та тестові облікові дані: не перенось їх у цей проєкт; адаптуй приклади до TypeScript і локальної конфігурації. Вихідне GitHub-репозиторій не декларує ліцензію — не копіюй і не поширюй його вміст поза локальним референсом без перевірки прав.
5. Не перенось код із `design-patterns-typescript` у цей проєкт без окремої перевірки прав: його CC BY-NC-ND 4.0 ліцензія обмежує комерційне використання та поширення похідних матеріалів. Якщо використовуєш код із MIT-шаблону, зберігай відповідне повідомлення про авторські права та ліцензію.
6. Не встановлюй залежності й не запускай тести референсів як частину кореневого проєкту. Каталог `reference/` виключений із ESLint-перевірки.
